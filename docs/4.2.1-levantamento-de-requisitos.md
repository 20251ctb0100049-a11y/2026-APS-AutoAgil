# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

Os requisitos do Auto Gil foram levantados em três passos. Primeiro, uma entrevista com o proprietário/gerente da oficina sobre a rotina de atendimento e diagnóstico. Depois, uma conversa com o mecânico/atendente para entender o registro de peças e serviços. Por fim, a análise das ordens de serviço em papel/planilhas usadas atualmente.

**A confirmar com o cliente:** [Anote aqui dúvidas pendentes, ex: prazo médio de orçamento ou política de garantia].

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Quero um sistema bonito para ver as ordens de serviço" (Gerente) | solução | Consultar o status de reparo do veículo rapidamente |
| F2 | "O cliente liga toda hora perguntando se o carro está pronto" (Atendente) | necessidade | Consulta clara do status do serviço |
| F3 | "Às vezes esqueço de anotar qual peça usei no carro" (Mecânico) | necessidade implícita | Vinculação de peças e serviços à ordem de serviço no momento da execução |

## Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como **atendente**, quero **cadastrar um cliente e seu veículo**, para **iniciar o atendimento na oficina**. | F1, F2 |
| HU02 | Como **mecânico**, quero **registrar os serviços e peças em uma OS**, para **manter o histórico do veículo atualizado**. | F3 |
| HU03 | Como **gerente**, quero **consultar o status das ordens de serviço**, para **informar o cliente sobre o andamento**. | F1, F2 |
| HU04 | Como **gerente**, quero **gerar o orçamento do serviço**, para **enviar para aprovação do cliente**. | F1 |

## Requisitos funcionais

| # | Nome | Requisito | Veio de |
|---|---|---|---|
| RF01 | Cadastrar cliente | O sistema deve permitir o cadastro de clientes. | HU01 |
| RF02 | Cadastrar veículo | O sistema deve permitir o cadastro de veículos vinculados a um cliente. | HU01 |
| RF03 | Criar ordem de serviço | O sistema deve permitir a abertura de uma ordem de serviço. | HU02 |
| RF04 | Adicionar itens à OS | O sistema deve permitir vincular peças e serviços a uma OS. | HU02 |
| RF05 | Consultar status da OS | O sistema deve permitir a consulta do status de uma OS. | HU03 |
| RF06 | Gerar orçamento | O sistema deve calcular e gerar o valor total do orçamento da OS. | HU04 |

## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
|---|---|---|---|
| RNF01 | desempenho | A busca por placa ou cliente deve responder em menos de 3 segundos. | características da 4.1 |
| RNF02 | acesso | Apenas usuários autenticados (gerente/atendente) podem alterar o status da OS. | características da 4.1 |
| RNF03 | dispositivo | O sistema deve funcionar em navegadores desktop e mobile sem instalação. | características da 4.1 |

## Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
|---|---|
| O sistema cadastra clientes e veículos. | RF01, RF02 |
| O sistema gerencia e abre ordens de serviço. | RF03, RF04 |
| O sistema permite a consulta de status da OS. | RF05 |
| O sistema calcula e gera orçamentos. | RF06 |

**Toda história tem requisito?** Sim, todas as histórias (HU01 a HU04) deram origem a requisitos funcionais.  
**Todo requisito tem origem?** Sim, cada requisito possui rastreabilidade direta com as histórias de usuário ou regras do negócio.
