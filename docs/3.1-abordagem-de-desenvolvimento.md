# 3.1 Abordagem de Desenvolvimento

O AutoAgil é desenvolvido de forma **iterativa e incremental**. Cada ciclo produz uma seção deste documento, na ordem em que a análise pede. Primeiro vem o que o sistema é (4.1). Depois vêm o que ele precisa fazer (4.2.1 e 4.2.2) e como ele é por dentro (4.2.3). O comportamento vem a seguir (4.2.5 e 4.2.4), e depois o que ele guarda (4.2.6) e como aparece para quem usa (4.2.7). A arquitetura (3.3) fica para o fim, quando todas as partes já existem.

No fim de cada ciclo, a seção nova é conferida contra as anteriores. Todo caso de uso precisa ter vindo de um requisito, e toda classe precisa aparecer em algum caso de uso. Quando algo não bate, a correção é feita na seção de origem, e a nova versão fica registrada no repositório.

A escolha tem dois motivos. Cada seção depende da anterior, e fazer o documento inteiro de uma vez deixaria os erros para o fim, quando corrigir custa mais. O cliente (Marcos) consegue validar cada entrega individualmente antes do avanço para a etapa posterior, evitando refazer diagramas e especificações. Como o projeto é desenvolvido por uma única pessoa, cerimônias do Scrum (como reuniões diárias) não são adotadas, mantendo-se apenas a prática de iterações curtas com entregas revisáveis.
