# 4.2.3 Modelagem de Classes

## Dos substantivos às classes

As classes do AutoAgil foram identificadas a partir da análise dos substantivos presentes no fluxo principal de *Agendar serviço* (seção 4.2.2) e na lista de requisitos funcionais da 4.2.1. Nem todo substantivo vira classe: alguns são meros detalhes (atributos), outros pertencem ao ambiente externo ou à interface com o usuário.

| Substantivo | De onde veio | Vira | Por quê |
|---|---|---|---|
| cliente | ator da 4.2.2, passo 1, RF02 | classe **Cliente** | o sistema registra quem é o cliente e guarda seu histórico de agendamentos |
| atendente | ator da 4.2.2, RNF01 | classe **Atendente** | precisa se identificar para alterar status de veículos e cadastrar serviços |
| nome, telefone | passo 3 do fluxo | atributos de **Usuario** | tanto o cliente quanto o atendente possuem identificação e contato no sistema |
| veículo, placa | passo 3 ("informa os dados do automóvel"), `«include»` | classe **Veiculo** | o carro é a entidade central do serviço no pátio; um cliente pode ter mais de um carro |
| serviço, tempo | passo 1, RF01 | classe **Servico** | representa os tipos de lavagem oferecidos, com preço e duração estimada |
| agendamento, data | passo 6, passo 7, RF03 | classe **Agendamento** | o registro principal que liga o cliente, o veículo, o serviço e a vaga do pátio |
| previsão de entrega | passo 5, RF06 | atributo de **Agendamento** | é um detalhe calculado no momento da reserva, não existe de forma isolada |
| prancheta, pátio | fala do cliente na 4.1 | nada | a prancheta é o processo físico antigo que o sistema substitui; o pátio é o espaço físico |

## Classes

Abaixo estão as classes do sistema com seus respectivos atributos (dados) e operações (comportamentos), indicando a origem de cada elemento

| Classe | Atributos | Operações | Veio de |
|---|---|---|---|
| **Usuario** | - nome: String<br>- telefone: String | + autenticar(): boolean | Passo 3 (identificação) e RNF01 (acesso do atendente ao sistema) |
| **Cliente** | *herda de Usuario* | + temPendencia(): boolean | Fluxo de Exceção E2 (validação de faltas sem aviso prévio) |
| **Atendente** | *herda de Usuario* | *nenhuma própria* | Distinção de perfil no sistema para autorizar o cadastro de serviços e alteração de pátio |
| **Veiculo** | - placa: String<br>- modelo: String<br>- marca: String | + validarPlaca(): boolean | Passo 3 e `«include»` Identificar veículo |
| **Servico** | - nome: String<br>- preco: double<br>- tempoEstimadoMin: int | + estaAtivo(): boolean | RF01 (cadastrar serviço com valor e tempo) e passo 1 do fluxo |
| **Agendamento** | - dataHorario: DateTime<br>- previsaoEntrega: DateTime<br>- status: String | + calcularEntrega(): DateTime<br>- + atualizarStatus(): void | Passo 5 e RF06 (cálculo de previsão), RF04 e RF05 (status do atendimento e retirada) |
